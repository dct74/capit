# Capit

一个菜单栏常驻的 macOS 截图标注工具（AppKit 纯程序化，无第三方依赖）。截图后自动加连续圆角 + 原生风格阴影，弹出右下角预览缩略图，点击即可进入标注编辑器；标注结果保存到桌面。也可直接从菜单导入本地图片进行标注。

当前版本：**v1.2.7**

## 功能特性

- **三种截图模式**（菜单栏或全局快捷键）
  - 全屏截图：`⇧⌘3`（也支持 `⇧⌘9`）
  - 区域 / 窗口截图：`⇧⌘4`（也支持 `⇧⌘0`）
- **交互式框选**：区域 / 窗口选择调用 macOS **原生选择界面**（`screencapture -i`）：拖拽框选区域；**空格**在「区域 ↔ 窗口」间切换；**ESC** 取消。原生界面**不激活本 app**，因此不会关闭前台 app 的菜单栏、展开菜单或浮层，行为与系统截图一致；窗口截图天然带圆角/阴影（会被“已处理检测”跳过二次处理）。
- **后处理**：连续圆角 + 原生风格投影，截图时播放系统快门声。**装饰在写盘那一刻才加**（详见更新日志 v1.1.1）：编辑器里标注的是原图，保存时再把圆角与投影套在标注结果外面。
- **自动拷贝到剪切板**（菜单可关，**默认开启**）：
  - 截图**当场**就把**成品**（已加圆角与投影）放进剪切板——不等预览消失，也不再临时放未标注版本。
  - 在编辑器里标注并保存时，**标注后的成品再替换一次**。
  - 除此之外剪切板**不会**被这个 app 再写（落盘、关闭编辑器未保存都不会），所以不会悄悄覆盖你在此期间复制的东西。
  - 导入本地图片不占用剪切板；导入后标注并保存的成品会拷贝。
- **右下角预览**：新截图**替换**旧预览（旧图立即落盘），只保留一张；点击进编辑器，超时自动落到桌面。
- **标注编辑器**（菜单「编辑器」或 `⌘E`）：
  - 工具：矩形 / 椭圆 / 箭头（90° 每臂，臂长=杆长 2/5）/ 直线 / 荧光笔 / 文字 / 序号 / 马赛克（纯色填充，默认黑）/ **高亮选区**。
  - **高亮选区**：拖出一个圆角矩形选区，**选区之外**压暗、选区本身保留原始亮度，效果像给非选区盖了一层遮罩；选区沿用与矩形相同的 Mac 连续圆角，边缘不是生硬的矩形切口。压暗强度由**工具栏滑杆**（「压暗」）实时调整，默认 50%。因为标注的是原图，压暗天然只作用于图片本身，投影是之后才加的、不受影响。
  - 荧光笔用 **Multiply 混合**（压在深色文字上文字依然纯黑）；软过渡宽度是**绝对的 3.5px**，不随笔宽变化——墨往纸纤维里渗是固定距离，不是笔尖的比例——层数因此恒为 18 层。笔迹两端为**平头 + 轻微收虚**（淡出 3px）且宽度全程满宽，既不是尖头也不是圆头；描边连接用 **bevel**，避免圆角连接的圆盘、尖角连接的尖刺在末端堆出多余的一团。笔迹中线叠了一点低频侧向扰动（周期随笔宽自适应、两端淡出），边界不像刀切一样完美。
  - 荧光笔用 **Multiply 混合**，边缘由多层宽度递增、浓度递减的描边叠加出连续的衰减（层数随笔宽自适应：细笔约 12 层、粗笔 18 层，否则层间台阶在粗笔上会摊开成可见的同心带）。笔迹中线叠了一点低频侧向扰动，边界不会像刀切一样完美；末端为平齐收口（停顿不会鼓出圆头）。
  - 支持颜色、线宽、实/虚线、字号；选中即**就地修改**（颜色/宽度/字号/实虚线）；`Cmd+S` 保存，`Cmd+Z`/`⇧Cmd+Z` 撤销重做，`Delete` 删除，**方向键移动选中图形**（`⇧` 加速）；数字自动排序。
  - 打开时默认不选中任何工具；线型/线宽在切换工具或形状时回到默认（实线 / 2，荧光笔 16）。
  - 荧光笔的光标本身就是一把尺子：光标高度**等于笔划粗细**，上下两条横杠就是笔迹的上下边缘，所以在调线宽时可以直接照光标预估成品粗细。
- **导入本地图片标注**（菜单「编辑器」）：支持 **png / jpg**，自动套用圆角 + 阴影后进入编辑器；保存时 **PNG 源覆盖原文件**，**JPG/JPEG 源转为同目录同名的 PNG**。
  - **已带圆角/阴影的图片不再重复处理**：Capit 自己导出的 PNG（内嵌标记）或 macOS 原生窗口截图（alpha/几何启发式判定）会原样打开，跳过二次圆角与阴影。
  - 关闭编辑器但未保存时**不会改写源文件**。
- **关于**：菜单「关于」显示当前版本。
- **自动退出（可选）**：默认不自动退出。可在菜单勾选「空闲 10 分钟后自动退出」，连续 10 分钟无截图/标注操作后自动退出（可用环境变量 `CAPIT_IDLE_SECONDS` 覆盖秒数，便于测试）。

## 运行环境

- macOS 13.0+
- Apple Silicon（arm64）
- 需要**屏幕录制**权限（截图功能）

## 构建与打包

本机约定：所有仓库统一放在 `~/Documents/projects/` 下，本项目路径为 `~/Documents/projects/capit`。

```bash
# 1) 克隆（若尚未克隆）
cd ~/Documents/projects
git clone git@github.com:dct74/capit.git
cd capit

# 2) 仅编译可执行文件
swift build -c release

# 3) 打 .app（ad-hoc 签名，写入 build/Capit.app）
./make_app.sh release

# 4) 启动
open build/Capit.app
```

产物 `build/Capit.app` 完全自包含（单可执行文件 + 图标 + Info.plist），无外部框架，可直接拷贝到别的 Mac。

## 更新日志

### v1.2.7
- **高亮选区不再挡住其它工具**：在亮区内起笔会**正常画新形状**，而不再先去选中那块高亮；**原地单击（不拖动）仍然会选中高亮**，所以它依旧可以调整压暗强度或被移动。拖动其它已画形状的行为不变。
  - 这样处理是因为本工程没有"取消当前工具"的状态，若亮区完全不吃点击，高亮一旦画上就再也选不中了。

### v1.2.6
一次代码审核后的清理与修复（无功能变化）：

- **修掉「拖动压暗滑杆会清空撤销记录」**：滑杆是连续触发的，原来每触发一次就存一份撤销快照——一次拖动就能产生 60 份，正好等于撤销上限，于是此前的编辑历史全被挤掉。现在一次拖动只算一步（拖完再开始新的一步）。
- **修掉渲染层的两处隐患**：文档图像原来是隐式解包（无文档上下文渲染会崩），改为可选并就地判空；图片遮罩缓存原来只按对象地址做键（地址被复用时会命中上一张图的遮罩），现在把尺寸也并入键。
- **装饰绘制改为纯 CoreGraphics**：原来用 `NSImage`/`NSGraphicsContext`，但它在后台线程执行（截图路径），而 AppKit 绘制不应在后台线程使用。**输出逐字节一致**（6 组尺寸、最大 280 万字节，差异 0）。
- **截图路径不再在写原图临时文件上耗时 42 ms**：编辑器直接用内存里的原图，跳过这次全尺寸 PNG 编码。
- **`InteractiveCapture.swift`（584 行）移入 `#if DEBUG`**：release 包里只有 DEBUG 自测路径用到它。
- 编辑文字后未做修改时，不再产生一条空的撤销记录。

### v1.2.5
- **修掉"窗口截图做了标注后，投影区域出现色块/奇怪图案"**。根因是保存时用于合成的像素缓冲区是**手动分配的未初始化内存**，而绘制采用 source-over：源图不透明的地方会被完全覆盖，但**透明与半透明的地方会保留缓冲区里的旧数据**。窗口截图恰好带投影（半透明）和透明边角，所以垃圾就露在投影区；区域/全屏截图整张不透明，因此一直正常。
  - 现在合成前先 `clear` 缓冲区；同时给 `applyingRoundedCorners` 与 `windowWithShadow` 两处同样会分配位图的地方补上了 clear（圆角切掉的部分同样必须是透明，而不是缓冲区残留）。
  - 复现与验证：故意用可识别的旧数据填充缓冲区 → 修前透明区残留 **16,000** 个垃圾像素，修后 **0**。

### v1.2.4
- **虚线标注：圆角矩形与椭圆不再在特征点处留空。**
  - 圆角矩形的**四个圆角中点**、椭圆的**长轴两端顶点**，现在必然落在一段虚线正中；其余部分按段精确铺满，不会因为尺寸变化而偶然把空白甩到圆角/顶点上。
  - 做法是把轮廓在锚点处切段，每段取 `n = round(L / 14)` 个周期、`p = L / n`，虚线样式配 `phase = dash/2`——于是每段两端各是半个虚线，相邻两段在锚点处合成一个完整的虚线，段内间距均匀，既不会重叠也不会出现双倍空隙。
  - 椭圆的锚点取**长轴两端**（长轴水平取左右、竖直取上下）。
  - 顺带发现并修正了一个几何错误：squircle 的参数 `k` **不是弧长**，`k=0.5` 实际落在直边附近（u≈0.5r、v≈0.027r），所以锚点改为 `u = v` 的位置（`k = 0.5^(1/n)`，n=3.5 时约 0.82）。
  - 实线绘制路径完全未改动。

- **矩形 / 椭圆 / 直线 / 箭头的默认线宽从 3 改为 2**，工具栏的线宽弹窗也随之默认选中 2。荧光笔不受影响（它是笔尖宽度，默认 16）。

### v1.1.8
- **窗口截图：圆角处再细腻一档。** 上一版的覆盖率只在离不透明核心 1 像素内生效，边界处直接归零；而**连续圆角的抗锯齿斜坡本身很宽**（沿对角线实测约 3 像素），于是边界上会留下一个小台阶。现在改为**按距离衰减**（1 像素内保持原覆盖，第 2 像素按 50% 计入），并对覆盖率做了 0.85 的轻微 gamma 补偿——半覆盖的边缘像素在眼睛里更偏向"被覆盖"的一侧，线性取会让亮边看起来偏薄。
  - 实测：边缘抗锯齿像素的平均压暗比例 0.32 → **0.34**、下限 0.16 → **0.20**（更贴合"看起来覆盖了多少就压暗多少"）；图片内亮像素仍有 **0** 个漏压暗。
  - 遮罩构建重写为单遍扫描 + gamma 查表：4K 约 **36 ms**（首版 103 ms）。

### v1.1.7
- **窗口截图：遮罩改为"带抗锯齿的覆盖率"**，不再用阈值切边。任何阈值都会在曲线上留下**一像素台阶**，那条台阶就是看起来的锯齿和断层。现在遮罩值直接取像素**自身的 alpha**（只在离不透明核心一像素以内），于是压暗的边界与图片自身的边缘一样平滑：
  - 实测（真实窗口截图，导出路径）：图片内 **1,920,361 个亮像素 0 个未被压暗**；边缘抗锯齿像素的比例淡出为 **0.16–0.49**（渐变的，不是一刀切）；被影响的投影像素 6,400（沿轮廓一像素，其中边缘那圈因 alpha 约 25/255 只被压暗约 10%，肉眼不可见）。

### v1.1.6
- **窗口截图：修掉四个圆角在"弧线接直线"处的压暗断层。** 上一版把图片遮罩的阈值定在"完全不透明"，于是图片**抗锯齿轮廓**被排除在压暗之外。这个被排除的宽度取决于角度：平直边只有 1 像素，而水平扫描穿过圆角弧线时是 15–20 像素——所以圆弧上留下一条未压暗的边，并在弧线接直线的地方断掉，看起来就是"错位/断层"。
  - 现在遮罩取"完全不透明区域"后**向外膨胀 1 像素**，把抗锯齿轮廓一起盖住；这一像素只在它本身的 alpha 达 55 以上时才取（窗口外侧的投影实测只有约 25，图片边缘的抗锯齿是 70 以上），所以不会额外压暗出一圈深色光晕。
  - 实测（真实窗口截图 2092×1298，导出路径）：图片内亮像素 **1,920,361 个中 0 个未被压暗**（断层消失），投影被影响的范围从 12,824 降到 **6,396** 像素（恰好是沿轮廓 1 像素的一圈，这是覆盖抗锯齿边缘所必需的代价）。
  - 遮罩构建 10 ms（4K 约 30 ms），每个编辑器会话一次。

### v1.1.5
- **窗口截图：修掉压暗区域边缘漏出的一像素亮边。** 上一版的图片遮罩是**半分辨率**构建后再向内收一像素的——收缩是为了让边界误差只落在图片内、不蹭到投影，代价就是边缘留了一圈约 1px 未被压暗的亮边。
  - 现在遮罩按**原始分辨率**构建，阈值边界就是图片自身的边缘，因此不再需要收缩，亮边与投影泄漏同时消失。
  - 实测（真实窗口截图 2092×1298，导出路径）：投影像素被压暗影响 **0 / 304,584**，边缘首像素未压暗的扫描行 **0 / 93**，图片区域 99% 正确压暗。
  - 成本：遮罩构建 3 ms（4K 约 10 ms），每个编辑器会话只建一次。

### v1.1.4
- **修掉"编辑时正常、保存后遮罩错位"**。根因是**同一份文档在两条渲染路径上尺寸单位不一致**：画布用的是**点**，而保存时把文档尺寸改写成了**像素**，偏偏导出时 CTM 还会把点放大成像素（`exportScale`）。于是保存时的压暗区域与图片遮罩都被放大了一倍，落在错误的位置——所以屏幕上对、落盘就错。
  - 现在文档尺寸只在画布初始化时发布一次（点），保存不再覆盖它。
  - 实测（真实窗口截图 2092×1298、导出路径按 `save()` 的 CTM 复现）：304,584 个投影像素中只有 **4** 个被压暗影响，图片区域 98% 被正确压暗。
  - 顺带删掉了已经无人调用的 `ImageProcessor.contentRect`（上一版用 alpha 遮罩取代了它）。

### v1.1.3
- **修掉窗口截图压暗错位**（v1.1.2 没修好的那个）。根因是遮罩的**坐标空间搞反了**：遮罩是从 alpha 通道自下而上读出来的，而它被用于**y 轴向下**的文档空间（画布与导出都是这个空间），于是整块遮罩**上下镜像**。窗口截图投影的留白是不对称的（下方比上方厚），镜像后就整体偏移，压暗因此漏到投影上。
  - 现在遮罩按文档空间的朝向重建，并在**真实窗口截图**（2092×1298、含系统投影）上实测：304,584 个投影像素中只有 **4** 个受压暗影响（修前 53,964），图片区域 99% 被正确压暗。
  - 区域截图（方角外边界 + 之后统一切圆角）不受影响，仍然完全重合。

### v1.1.2
- **修掉高亮选区的两处错位。**
  - **窗口截图**：这类截图（含系统自带的圆角与投影）不是由 Capit 的装饰流程生成的，所以"按装饰留白反解内容区"的算式对它并不成立，遮罩因此整体偏移。现在改用**图片自身的 alpha 通道**生成遮罩，遮罩严格跟随图片实际轮廓（半分辨率构建后向内收一个像素，确保误差只会落在图片内、不会蹭到投影）。
  - **区域截图**：压暗区域的外边界原本画了一条圆角，但成品的圆角是 `max(14px, 0.042 × 短边)`，标注工具用的是半宽的 20%，两者永远不可能重合，于是四个角内侧留下亮的楔形。现在压暗区域的外边界直接用**文档边缘（方角）**，由图之后的装饰步骤去切圆角——这样压暗边界与成品圆角、以及外加的投影**天然完全重合**。
- **顺带修回一处回归**：装饰延后之后，全屏截图丢了原本更紧的圆角比例（0.03），现在这个比例随截图一起传到写盘环节，全屏/区域各自保持原来的观感。

### v1.1.1
- **装饰改为"写盘时才加"**（圆角 + 投影）。原来是截图后立刻加装饰，于是投影的透明留白成了标注文档的一部分，带来三个连带问题：标注可以画进留白里、压暗会连投影一起压暗（v1.1.0 为此加了内容区反解）、任何"作用于整图"的效果都得特殊照顾这圈留白。现在：
  - 编辑器里标注的是**原图**，保存时才把圆角与投影套在**标注结果**外面，所以投影包住的是最终成品（含标注）。
  - 高亮选区不再需要内容区反解，直接"整幅 − 选区"；标注也不可能落到留白里。
  - 剪切板拿到的是**成品**（与落盘的文件一致），在落盘那一刻写入——所以无标注时大约延迟到预览消失（约 4 秒）才可见。
  - 代价：无标注的路径不再是"文件移动"，而是落盘时**解码 → 装饰 → 编码**；实测 4K 装饰约 180ms，在后台线程完成，不影响交互。另外编辑器与预览显示的是未加装饰的原图（预览本身会画投影，看起来几乎不变）。
  - 投影留白的反解（`ImageProcessor.contentRect`）只保留给"导入时已经带装饰"的图片，因为只有那种文档真的含留白。

### v1.1.0
- **新增工具「高亮选区」**：拖出一个圆角选区，选区**之外**的画面压暗、选区本身保持原始亮度——相当于给非选区盖一层半透明黑遮罩。选区沿用矩形工具那套 **Mac 连续圆角（squircle）**，不是生硬的矩形切口。
  - **压暗强度可调**：工具栏新增「压暗」滑杆（0.05–0.95），实时生效，默认 0.5。它复用形状的 `opacity`，所以选中已画的选区再拖动滑杆就是调整那一个。
  - **只压暗图片本身，不压暗投影**：处理过的截图把投影作为透明留白烘进了图片里。遮罩现在按图片内容区裁剪（由 `ImageProcessor.contentRect` 从文档尺寸反解出内容矩形，三种模糊区间都实测精确可逆），所以投影保持原样。
  - 遮罩叠在已有标注之上，对截图内容和下面的标注都生效。

### v1.0.4
- **圆角矩形标注：内外圆角差减半，且不再出现"胖圆角"。** v1.0.4 的第一版为了做到"内外半径完全相等"，把内外各画成一条同半径曲线——结果圆角处墨带厚度涨到线宽的 **1.41 倍**，四个角看起来发厚。这两件事在几何上是互斥的：**墨带等宽 ⇒ 内外半径必然相差一个线宽；内外半径相等 ⇒ 圆角处必然可厚到 1.41 倍**。现在改为折中参数 `cornerBalance`（默认 0.25）：内外半径差从 1 个线宽降到 **半个线宽**，圆角墨带厚度从 1.41 倍降到 **1.10 倍**。想要更"等半径"就把 `cornerBalance` 调大（0.5→差 0.5w/厚 1.21w），想要"纸带等宽"就调回 0（差 1w/厚 1.00w）。

### v1.0.3
- **菜单栏图标尺寸调整**：图标尺寸改为一个可直接控制的常量（`statusIconPointSize`，当前 17pt，2x 屏上实际画出 33px，比初版小 9px）。
- 为定位"图标看起来偏小"这个问题，实测确认（在真实 status item 上按像素量）：**菜单栏是按图像自身的尺寸绘制的**，SF Symbol 自带的那圈空白边距既不会参与计算、也不会被缩放掉——所以**"减小留白"并不能让图标变大**，只有 `pointSize` 有效（约 0.97 倍关系：15→29px、17→33、20→38、22→42、24→46）。期间实现过一版"裁掉留白再补留白"的方案，实测对画出的尺寸毫无影响，已移除。

### v1.0.2
- **新增：自动拷贝到剪切板。** 截图**当场**就把未标注的图放进剪切板，因此不点预览、不打开编辑器也有图可粘贴；在编辑器里标注并保存时，标注后的成品会替换掉它。截图和保存两处都走同一条路径（PNG + TIFF，编码在主线程之外完成，4K 图不会卡顿）。
- 菜单新增「拷贝到剪切板」开关（位于「空闲 10 分钟后自动退出」之上），**默认开启**，关掉后两处都不再写入。
- 编辑器的保存即使写盘失败也会先把成品放进剪切板——标注结果不会因为一次写盘错误而丢掉。

### v1.0.1
- **荧光笔边缘重做为连续渐变。** v1.0 的边缘是"湿边 + 笔芯"两遍描边，会在边缘留下一条可见的台阶，而且墨色只有 0.5 浓度上限。
  - 软过渡宽度改为**绝对的 3.5px**（原为半宽的 43%）：墨往纸纤维里渗是固定距离，所以 240px 宽的笔尖不该有 30px 的软边。层数因此**恒为 18 层**，不再随笔宽爬到 40 层，全幅重绘也随之变快。
  - 两端改为**平头 + 轻微收虚**（淡出 3px）：把承载浓度的内层按浓度截短、让最宽最淡的几层贯通到底，所以末端像上下两边一样淡淡收虚，**而宽度全程满宽**——既不是尖头，也不是圆头。
  - 描边连接改用 **bevel**：圆角连接会在每个顶点填一个半径等于半宽的圆盘，尖角连接会甩出半个笔宽的尖刺，两者都会在末端堆出多余的一团。
- **修掉笔迹末端偶发的一团墨**（停留时间稍长、或采样节奏刚好时出现）。根因是**平头端帽被转过角度**——端帽垂直于它所在的线段，线段一旦被转过角度，端帽就会沿笔迹方向戳出半个笔宽。同时修掉两个诱因：侧向扰动的周期短于采样间距而被混叠成逐点抖动；重采样可能留下极短的末段，而短线段上的微小侧移等于大角度。
- **修掉纸纹的横向拉丝**：`draw(image, in:, byTiling:)` 会先把图像缩放到填满矩形再平铺，因此按笔迹包围盒平铺时纸纹被沿笔迹方向拉伸约 4.5 倍（实测自相关比 1.49–4.35）。改为按原始像素尺寸手工铺贴后恢复各向同性（1.00）。
- **修掉颗粒浓度补偿失效**：颗粒只减墨，原来把浓度旋钮顶在饱和点，中心浓度无论怎么调都停在 0.78。
- **荧光笔光标改成"尺子"**：光标高度精确等于笔划粗细，上下两条横杠就是笔迹的上下边缘，调线宽时可直接照光标预估成品粗细。
